# DeepSeek 调用耗时排查（2026-11-02）

输入为“我想办一个活动”，首次进入活动创建流程。

## 原始轮次

| 环节 | 耗时 | 是否阻塞用户回复 |
| --- | ---: | --- |
| 路由 `route` | 1828 ms | 是 |
| 槽位抽取 `extract_slots` | 3212 ms | 是 |
| 流式追问 `ask_missing` | 3760 ms | 是 |
| 其余工作流开销 | 108 ms | 是 |
| 合计 | 8908 ms | 是 |
| 长期记忆 `extract_memory` | 1495 ms | 否，回复结束后后台执行 |

主要耗时是三次串行模型调用。路由、抽取依赖前一步结果，追问要在抽取结束后才能开始。
后台记忆解释了页面的“模型调用 4 次”，但不应再加进这轮的 8908 ms。

## 真实 API 对比

使用该轮次记录的三组真实提示词，以及当前配置的 Key 和 `deepseek-flash`。
每组交替测试默认模式、`reasoning_effort: none`、`none`、默认模式，共 12 次短调用。
测量从发出请求到完整返回、以及第一个非空正文片段的时间；思考片段不计为用户可见正文。
对比调用统一使用流式协议和 2048 token 上限，原来的路由、抽取使用非流式，因此此表用于比较模式，不能等同于完整工作流耗时。

| 调用 | 默认模式完整耗时中位数 | none 完整耗时中位数 | 默认模式首段正文中位数 | none 首段正文中位数 |
| --- | ---: | ---: | ---: | ---: |
| 路由 | 1340 ms | 1419 ms | 1149 ms | 1200 ms |
| 抽取 | 1745 ms | 1324 ms | 1657 ms | 1173 ms |
| 追问 | 2179 ms | 1471 ms | 1861 ms | 1135 ms |

各环节中位数之和约 5.26 秒 → 4.21 秒，减少约 20%。路由没有稳定改善。
默认模式在 6 次请求中的 5 次返回了思考片段；none 的 6 次均无思考片段。
两种模式的路由均正确，槽位均返回空值，追问内容符合缺失信息。

DeepSeek 当前 API 在未指定思考参数时默认开启思考；`reasoning_effort: none` 可关闭。
参见 [DeepSeek Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)。

样本较少，存在服务端负载、连接建立、提示词缓存和输出长度的影响，不能保证固定提速比例，
也不能将原截图的 8.9 秒与这里的 none 数值直接用于计算配置带来的提速。

## 已应用的优化与验证

- 新增可选 `flow.model.reasoning-effort`，框架默认留空，保持供应商默认行为。
- 当前 Demo 配置为 `none`，主模型、路由、流式和记忆模型都生效。
- Trace 的请求参数新增 `reasoningEffort`，便于确认配置是否真正发出。
- 本地 HTTP 测试验证四种模型均透传该参数，未配置时请求体不包含该参数。
- 原有 7、8 参数的模型配置构造器保留，已有工作流与 stub 测试可继续使用。

另外启动临时 8081 测试实例，使用真实模型跑了两次完整 SSE 工作流，均为独立 `perf-none-*` 会话，
不绑定用户，不触发长期记忆抽取；测试完成后已停止临时实例。

| 测试轮次 | 首个用户可见片段 | 工作流完整耗时 | 节点路径 |
| --- | ---: | ---: | --- |
| 1 | 4784 ms | 5118 ms | router → collect_target |
| 2 | 2637 ms | 3030 ms | router → collect_target |

两轮实际请求记录均为 `reasoningEffort=none`，并正常追问年龄、性别和区域。
第一轮还包含测试 JVM 和客户端首次调用开销；两轮结果不代表稳定延迟分布。

## 后续进一步降低等待时间

若需要更快出现第一句话，主要方向是减少用户等待链路中的模型调用次数：
例如由路由结果同时提供首阶段抽取信息，或让业务节点为无新信息的初次进入提供固定追问。
这些方案会改变节点职责或回复生成方式，需要单独验证多轮补充、修改、插话等行为。
当前改动只增加可配置的思考强度，没有改变路由或槽位处理流程。

配置生效需要重新构建并重启实际运行的应用。使用其他供应商时，先确认其是否支持 `reasoning_effort`；
删除该配置即可恢复默认模式。
